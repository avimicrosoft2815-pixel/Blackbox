A RECORDER FOR AI APPLICATIONS · IN DEVELOPMENT

When the stream breaks, you get the film of what happened — not a story about it.

One command puts a recorder in front of any OpenAI-compatible call, without changing the application. When something goes wrong you get three things you can check: a capsule you can verify, a diagnosis that names what it cannot establish, and a repair that a person approves by token.

01 · THE JOURNEY

Sixty seconds, five commands

This is the whole of it: install, point it at a model, break something, read the evidence, approve a repair. Every block below is the command that was typed on the machine that built this page — not a summary of it — and the ran here marks the ones that were executed to write this page.

  1. 01

    Install it

    ran here 
    git clone https://github.com/avimicrosoft2815-pixel/Blackbox
cd Blackbox
python -m venv .venv && . .venv/bin/activate
pip install -e .

    Python 3.11 or newer, the standard library at run time, and nothing else. The recorder writes capsules into a data directory you name; it installs no service and opens no port to the outside.

  2. 02

    Point it at any OpenAI-compatible model

    ran here, against a loopback provider 
    blackbox run --upstream 'openai=https://api.openai.com/v1@/openai' -- python your_app.py

# a local runtime — same command shape, different base URL
blackbox run --upstream 'openai=http://127.0.0.1:11434/v1@/openai' -- python your_app.py

# a gateway you answer on your own path
blackbox run --upstream 'openai=https://gateway.example/v1@/gateway' -- python your_app.py

    The @/openai suffix is the path the recorder answers on: it points the client's base-URL variable at itself, so the application is unmodified and never learns it is being recorded. Any OpenAI-compatible base URL works the same way — hosted, local or a gateway — because the recorder speaks the client's protocol, not a vendor's. What ran here is the same flag against a loopback OpenAI-compatible mock (the third line of incident/run_demo.sh): a hosted endpoint needs the network, which this environment does not have, so that half of the sentence is a shape, not a measurement.

  3. 03

    Break something, then look

    ran here 
    blackbox ls --data data
blackbox verify data/capsules/*.bbx
blackbox view data/capsules/<id>.bbx --out evidence.html

    ls lists the capsules in a directory, verify re-derives every part against the capsule's own frames and prints the checks it cannot recompute instead of counting them, and view writes one offline HTML file you can hand to somebody who has nothing installed.

  4. 04

    Ask what it means

    ran here 
    blackbox diagnose data --json
blackbox diagnose data --out report.md --brief brief.md

    Findings arrive with the evidence that supports them, the alternatives that are not ruled out, and the check that would separate them — plus a list of what the capsule cannot answer at all.

  5. 05

    Approve a repair, then prove it

    the shape of the command, run in the repository's tests 
    blackbox repair preview proposal.json          # prints a token
blackbox repair apply proposal.json --approve <token>
blackbox repair verify proposal.json --test "pytest -q"

    A proposal is data; it is never executed. Applying it needs the token that preview printed, and verify runs the check you named — the tool's own output stays on screen next to the result, so a pass is not mistaken for a proof.

The whole incident behind the film reproduces in about six seconds: BLACKBOX=../../.venv/bin/blackbox PYTHON=../../.venv/bin/python bash incident/run_demo.sh /tmp/bbdemo. It is a synthetic order desk and a loopback provider that cuts the stream; every id in it is invented.

02 · WHY THIS EXISTS

What used to be expensive to build

None of this is a new idea about how to record software. What is expensive is the joining up: the proxy at the seam, the ids that match across two processes, the artefact you can hand to someone else, the diagnosis that does not overstate itself, and the repair a human actually approved. BlackBox is that, wired together, with the limits printed on it.

what you would build yourselfwhat it costswhat is here
a proxy that sees both sides of the call one per SDK, kept in step with each release blackbox run — the app is unmodified, the proxy is loopback only
an id that joins the app, the client and the wire thread it through every layer, and the day it breaks is the day you need it one run id; the launcher and the SDK capsules are linked to it and to each other
evidence somebody else can check exports, log buckets, hope a capsule plus verify, and one offline HTML page per capsule
a diagnosis that admits its limits usually nobody writes one, so a plausible sentence becomes a fact findings with their alternatives and the next check; a cannot_know list
a repair that a person approved an agent with write access and no receipt data-only proposals, a token from preview, and verify with the check you named
the same thing on every vendor a new integration per provider any OpenAI-compatible base URL, by name or by path prefix

What it costs you: this is pre-alpha, there is no hosted service, there is no account, and the capsule stores content as hashes in this demo — so the evidence answers what happened and in what order, not what the prompt said.

03 · WHAT IS PROVEN, AND WHAT IS NOT CLAIMED

Nothing here is “100% safe”. Here is what was tested instead.

A recorder sits next to your data, so vagueness is worse than a limit. The honest claim is a list: these checks run, these ones do not cover everything, and here is how to re-run them yourself. Numbers on this page are written by tools/stats.mjs from commands it ran at the commit named under them.

Measured, in tests that run

  • Secrets stay out of every sink. One corpus, every place a capsule can write, each asserted — tests/test_redaction_every_sink.py.
  • A tampered capsule is refused, not rendered — tests/test_capsule_attacks.py.
  • Nothing leaves the machine: the proxy can only reach the endpoints in its own table — tests/test_no_egress.py.
  • Verify does not count what it cannot recompute: an uncheckable check is printed as declared — tests/test_verify_cli.py.
  • Markup cannot execute in the pages the viewer writes — tests/test_xss_corpus.py.
  • No marketing absolutes in code, docs or commit messages — tests/test_forbidden_words.py.

Not claimed

  • That any of this makes a system safe. A recorder records; it does not sandbox the application it runs.
  • That the evidence is complete. Coverage depends on the integration and capture settings, and the film says so on the frame.
  • That a diagnosis is the cause. Each finding lists the alternatives it has not ruled out.
  • That a repair is correct. It is approved by a person and checked by the command that person named.
  • That any of it has been run on your provider, your OS or your model. The numbers below name the machine they came from.
