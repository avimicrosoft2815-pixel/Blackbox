## 0. The one-paragraph verdict

The *problem* (record → inspect → diff → replay LLM/agent runs) is established, the *category* is crowded, and the *name* is taken many times over: I found at least **ten** independent projects shipping under "flight recorder" / "black box recorder for AI agents" in 2025–2026, plus a 20-year lineage of generic software flight recorders (JFR, LTTng snapshot mode, Perfetto triggers, Go 1.25 `FlightRecorder`, dotnet-monitor collection rules, MongoDB FTDC, Oracle ADR incident packages, Sentry breadcrumbs). Every individual BlackBox feature exists somewhere. What I did **not** find in this search is one tool that (a) journals an LLM request *before* the network call and preserves partial streams so a `kill -9` leaves an "interrupted call" rather than silence, (b) does that from **three vantage points at once** — in-process SDK semantics, a language-agnostic local proxy, and coding-agent hook events — merged into **one** causally-ordered local tape, and (c) freezes a portable, LLM-readable incident capsule on agent-specific triggers (loops, budget blow-ups, invalid tool JSON, stream stalls) with a last-good-run diff. That combination is a credible *engineering and product* differentiator. It is not a "never done before" concept, it is not patent-grade novelty on the evidence here, and the honest positioning is "the first one you can attach to anything in one command, that doesn't lose the call that was in flight when the process died" — stated as a tested guarantee, not a slogan.

## 1. What is actually being proposed (from the brief)

`[Spec]` A Python-first, local, no-account recorder for LLM agents/RAG/LLM apps that:

- Instruments code via `@workflow/@agent/@tool/@retrieval/@step` + context managers, and auto-captures OpenAI/Anthropic SDK traffic by intercepting `httpx`/`httpx2`.
- Writes a **request event before the provider call proceeds**, then response/stream-chunk/error events, so a call that was in flight at process death is marked *interrupted*.
- Persists redacted events into a per-process **memory-mapped ring tape** (seq numbers, length framing, checksums, committed head, wraparound), **spills** still-open runs when the ring wraps, and tracks gaps.
- Detects clean exit, exceptions, signals, stalls, loops, budget overflow, provider errors, invalid tool JSON, rate limits, truncation, refusals, custom rules.
- Recovers open runs from dead processes and builds portable **`.bbx` incident capsules**: execution graph, prompt/model settings, cost, first divergence vs last-good run, captured responses, offline replay materials, generated tests.
- Local CLI, exports, replay/testgen, MCP, optional local daemon/API/viewer (daemon = optional index, not source of truth).
- Stated limits: Python only; HTTP capture limited to supported clients/provider formats; tape survives **process death**, not power loss inside the sync interval; replay feeds recorded responses (does not make the model deterministic); cannot detect hallucination by itself; most subsystems unvalidated beyond throwaway prototypes (`kill -9` tape trial, write microbenchmark, mocked SDK interception).

`[Spec]` The founder's wider vision adds: a general backend flight recorder (HTTP, DB, external APIs, handled errors, state changes), ~24 h rolling compressed buffer, last ~60 s frozen on incident as a portable "crash replay", local viewer, share with colleague, hand to any LLM for diagnosis; targets <50 MB RAM / <2 % CPU (unmeasured).

## 4. Five-level novelty judgment (format required by the brief)

- **Problem novelty:** not new. Recording/inspecting/replaying agent runs is the stated purpose of ≥15 projects above; generic software flight recording dates to at least 1997 (US6282673B1) and JFR.
- **Product-category novelty:** not new. LLM observability (Langfuse, Phoenix, LangSmith, Braintrust, Weave, AgentOps), agent record/replay (Tracewake, traceon, AgentReplay), agent audit recorders (AgentLens, Tracekit), traffic record/replay (Keploy, VCR) are all live categories.
- **Feature novelty:** none of the individual features is new (table §3). The only feature I could not match exactly is *crash-consistent preservation of in-flight LLM calls including partial streams, surfaced as an "interrupted" node after recovery*.
- **Architecture novelty:** the *combination* (pre-call journal + local bounded tape + process-death recovery + agent-pathology triggers + capsule + last-good diff + offline replay/testgen + multi-vantage capture) was **not found in one tool** in this search. Caveat: "not found" ≠ "does not exist"; search covered English/Chinese GitHub READMEs, docs, three patents, and secondary comparisons on 2026-11-14; private products, non-indexed repos, and patent full-text were not exhaustively searched. This is not a legal patentability opinion.
- **Implementation/market differentiation (where you can actually win):** (1) one-command attach across surfaces (Python SDK, base-URL proxy, coding-agent hooks, MCP, OTLP ingest) feeding **one** tape format; (2) the in-flight guarantee, *tested* with kill-at-every-write-boundary; (3) agent-specific trigger library with Perfetto/dotnet-monitor-style limits; (4) capsule that is also valid HAR + OTLP-JSON so every other tool can read it; (5) no account, no daemon required.

**Closest prior art (ranked by overlap):** Jiangxianze AFR (artifact/redaction/diff/replay), traceon-replay + Tracewake (replay/divergence/pytest), AgentOpsSec agent-flight + AGENTBOX (wrap-any-command launcher), AgentLens (flight-recorder positioning + alerts), llm-cassette (httpx-level stream capture), JFR/LTTng/Go FlightRecorder/Perfetto/dotnet-monitor (ring + trigger + snapshot mechanics), Keploy (generic traffic record/replay/testgen), Sentry breadcrumbs + Datadog Exception Replay (pre-incident trail + state at failure).

**Potentially distinctive part (one sentence):** a transparent recorder that commits each LLM request and every streamed chunk to a local crash-recoverable journal *before* the application sees it, merges in-process, proxy-level and agent-hook vantage points into one causally ordered tape, and freezes an interoperable incident capsule on agent-specific triggers — none of which I found combined in a single identified tool.

**Recommended truthful wording:** "A local flight recorder for LLM apps and agents that you can attach in one command to almost anything, and that keeps the call that was in flight when your process died." Avoid "first ever", "unique", "never done before", "zero loss", "deterministic", "secure".

## 5. Architecture critique (what I would change before writing code)

**C1 — "mmap ring survives `kill -9`" is a page-cache property, not an mmap property.** Any `write()` to a regular file also lands in the kernel page cache and survives the writing process's death; only kernel crash/power loss need `fsync`/`msync` ([LWN](https://lwn.net/Articles/457667/)). So mmap buys *latency* (no syscall per event) and *cross-process visibility*, not durability. It adds torn-page semantics, Windows `FlushViewOfFile` differences, and a fixed-size file you must pre-allocate. `[Proposed]` Keep mmap only if the benchmark proves the syscall cost matters at your event rates (it usually does not at tens of events/sec per process); otherwise use `O_APPEND` writes with the same framing/CRC. State the linearization point explicitly: *an event is "crash-recoverable (process-death class)" once its frame bytes and the length prefix are in the page cache; "power-loss durable" only after `fdatasync` returns.*

**C2 — A single wrapped ring + spill files is the wrong primitive for a 24 h buffer.** You are re-deriving segment logs the hard way: JFR, Chronicle Queue and Kafka all use **rolling segment files with size/age retention**; "spill" becomes "don't delete a segment that still has an open run" and "gap" becomes "segment N was retained but N-1 was evicted". `[Proposed]` Tape = directory of fixed-max-size segments (`seg-000123.bbt`), each with a header, framed CRC32C records, and a footer written on roll; retention by total bytes and age; an open-run index file. Ring semantics only inside the *current* segment if you keep mmap.

**C3 — The headline guarantee is buried.** The brief spends more words on ring mechanics than on the one behaviour nobody else documents: *request committed before call, chunks committed as they arrive, recovery surfaces an "interrupted at chunk k after t ms" node.* `[Proposed]` Make this the acceptance test #1 (kill at every write boundary: before request frame, mid-frame, after frame before head, mid-stream, after last chunk before close) and the first line of the README. Quantify the per-event latency it costs.

**C4 — Patching `httpx`/`httpx2` internals is the most fragile possible seam.** OpenLLMetry patches SDK *public* methods; llm-cassette uses the httpx *transport* layer and lists exact tested version pairs (openai 3.0/3.34, httpx 0.27/0.28, httpx2 2.7/2.13). `[Proposed]` Layered capture with a compatibility matrix and fail-open: (a) if the app constructs the client, offer `blackbox.wrap(client)` / `http_client=` injection (stable public API); (b) otherwise patch SDK public methods (`chat.completions.create`, `messages.create`, `responses.create`, their async/stream variants) and read **the SDK's own parsed stream events** rather than raw SSE bytes; (c) fall back to a loopback **reverse proxy** via base URL, which also works for every other language. Detect version drift at import (hash the wrapped function's `__qualname__`/signature; refuse to patch unknown versions; log one warning; never raise into user code).

**C5 — "Python-only, zero-dependency Python core" contradicts "usable on every device".** The tape writer, recovery, and capsule builder are small; write them **once** in a compiled language and ship: a single static CLI/proxy binary (Linux/macOS/Windows/arm64), a C ABI, and bindings (PyO3 for Python, napi for Node, WASM for the browser extension/viewer). `[Alternative]` Keep the pure-Python MVP but freeze a **language-neutral tape spec** (byte layout, CRC, seq, schema version) on day one so Node/Go/Rust writers can be added without a format migration. `[Open]` Owner decision: compiled core now (slower start, universal later) vs Python-first (faster start, port cost later). My recommendation: Python SDK first, but the *proxy/CLI* as a compiled binary from phase 2, because the proxy is what makes it attach to anything.

**C6 — Trigger semantics need the Perfetto/dotnet-monitor shape.** Named triggers; each with a window, threshold, `stop_delay` (how long to keep recording *after* the trigger so you also capture the aftermath), **cooldown and max-fires-per-24 h**, and fingerprinting for dedupe. Drop "refusal" and "hallucination" from automatic triggers; keep them as *manual flags* (`blackbox.flag("bad_answer")`, CLI `blackbox mark last`) or user-supplied predicates. Trigger evaluation must be fail-open and itself emit an event when it errors.

**C7 — Don't invent a closed capsule format.** `.bbx` should be a ZIP whose members are standard where standards exist: `manifest.json` (format version, hashes, redaction profile), `events.jsonl` (your envelope, with `gen_ai.*` attribute names where they map), `http.har` (every provider call as HAR 1.2 so Chrome DevTools/Proxyman open it), `otlp.json` (trace export so Langfuse/Phoenix/AgentLens ingest it), `blobs/` (content-addressed, redacted), `graph.json`, `cost.json`, `diff.json`, `replay/` (cassette), `tests/` (generated). Validate on import: zip-slip, entry size caps, decompression ratio, schema, no executable members.

**C8 — Replay/testgen and first-divergence diff are table stakes, not differentiation.** traceon, AgentReplay, Tracewake and llm-cassette already fail closed on divergence, block sockets, and emit pytest items. Match that contract (strict mode, by-key mode, network guard, JSON-path divergence report) and spend design effort on the parts they lack (recovery of *interrupted* runs into replayable cassettes with an explicit truncation marker).

**C9 — You have no tamper evidence; everyone else in the "flight recorder" naming space does.** A per-segment SHA-256 chain costs almost nothing and lets a capsule be verified offline. Position it as "verifiable", not "secure".

**C10 — Resource targets are fiction until measured.** FTDC's "<1 % CPU, ~1 MB/h" is for metrics, not prompt payloads. Prompt/response bodies dominate; at content-capture-on, a busy agent produces tens of MB/h. `[Proposed]` Benchmark matrix: disabled / decorators only / auto-hook content-off / content-on / fdatasync-per-event; event sizes 200 B, 8 KB, 200 KB, stream chunks; threads × asyncio; p50/p95/p99 added latency on a mocked provider; disk growth per hour.

**C11 — An in-process keeper thread cannot reliably detect its own interpreter's hang.** Under the GIL, a stuck C extension or a deadlocked event loop can starve the keeper. Crashpad's lesson applies: hang/segfault/OOM detection needs an **out-of-process** observer (the `blackbox run` launcher or the daemon) reading a heartbeat file/mmap page. Make the launcher the *recommended* mode, not optional.

**C12 — Serverless breaks the local-tape story.** Lambda freezes the environment right after the handler returns and loses buffered telemetry unless flushed ([OTel Lambda #2537](https://github.com/open-telemetry/opentelemetry-lambda/issues/2537)). `[Proposed]` A "flush-at-boundary" mode (sync write + optional ship to a sink before return) and an explicit statement that process-death recovery does not apply to frozen/ephemeral runtimes.

**C13 — The founder's competitor hypothesis is partly wrong and must be narrowed.** Sentry keeps a rolling local breadcrumb trail shipped on error; Datadog captures local variables at exception time and can generate a mocked integration test; Keploy records real traffic incl. DB and replays it as tests. The defensible gap is therefore: *local-first, no account, LLM-semantic (prompts/streams/tools/cost), crash-consistent for in-flight calls, attachable without code*. Say that; don't say "APM can't do this".

**C14 — Consumer ChatGPT/Claude apps cannot be observed "by running beside them".** Supported routes: API clients → base-URL proxy; Claude Code/Cursor/Codex/Gemini CLI → hooks (+ base URL for raw traffic; Claude Code honours `ANTHROPIC_BASE_URL` even with a subscription token per the llm-visuals README); Claude Desktop/ChatGPT → an MCP server that only sees calls routed to it; web UIs → extension with MAIN-world fetch patch; ChatGPT desktop → `[Not found]` any client hook; network proxy with CA only if the app isn't pinned. Write this matrix into the docs so nobody expects magic.

**C15 — Scope: keep the general backend recorder out of v1.** Keploy shows what it costs (eBPF, root, Linux, protocol decoders per DB). Your v1 wedge is the LLM call boundary, where a plain HTTP reverse proxy already gives language independence without root.

## 7. Recommended shape (so the critique is constructive)

`[Proposed]` — each item marked **recommended / alternative / open**.

1. **Tape spec v1 (recommended):** language-neutral, versioned; segment files, framed records `{len u32, crc32c u32, seq u64, ts_ns u64, kind u16, schema u16, payload}`; redaction *before* framing; content-addressed blob store with size caps; open-run index; per-segment hash chain. Written once, read by every component.
2. **`blackbox` single binary (recommended from phase 2):** `run` (launcher + out-of-process watcher + immediate recovery), `proxy` (universal LLM reverse proxy, journal-before-forward, SSE tee), `recover`, `inspect`, `capsule`, `diff`, `replay`, `export --md|--har|--otlp`, `view` (static, loopback-only), `attach <claude-code|cursor|codex|gemini>`, `mcp`. Alternative: pure Python CLI first (faster), compiled later (port cost).
3. **Python SDK (recommended first):** `install()/uninstall()`, decorators, SDK public-method capture with version matrix and fail-open, pre-call journal, stream chunk commits, contextvars propagation (documented unsupported: fork without re-init, free-threaded builds until tested), `flag()`.
4. **Trigger engine (recommended):** rule = source + window + threshold + `stop_delay` + cooldown + 24 h cap + fingerprint; built-ins for exception, exit code, SIGTERM/SIGINT, stall, stream stall, loop (identical request hash ×N), budget, max steps, 429/5xx bursts, invalid tool JSON; manual flag. Evaluation fail-open.
5. **Capsule (recommended):** ZIP of standard parts (§5 C7); import validation; "interrupted" nodes carry `last_chunk_index`, `elapsed_ms`, `partial_text_hash`.
6. **Durability matrix (recommended wording):** process death → committed frames + in-flight request + received chunks survive (test: kill at every boundary); interpreter hang → detected by launcher/daemon heartbeat, tape sealed externally; OS crash/power loss → only frames before last `fdatasync` (interval configurable, per-event sync optional, cost measured); disk full/permission loss → recorder disables itself, emits one gap event if it can, app continues.
7. **Zero-budget distribution (recommended):** PyPI + GitHub Releases (static binaries) + Homebrew tap + `npx` wrapper; unsigned binaries first (document Gatekeeper/SmartScreen friction), signing deferred (costs money); no hosted service in v1; optional daemon is a local process, not a cloud.

## 8. Where "out-of-this-world" is honestly reachable

1. **One-command attach to 10+ surfaces, one artifact** — nobody in §2.1 covers more than one or two surfaces; most are SDK-only or MCP-only. This is a packaging/engineering moat, not a research one.
2. **The in-flight guarantee, proven** — publish the kill-boundary test suite and the recovered capsules as evidence; competitors' READMEs admit the opposite (AFR-Java: buffered events lost when not flushing per event; OTel: un-ended spans not exported).
3. **Cross-vantage causality** — proxy sees the model call, SDK sees the tool/step, hooks see the agent turn; merging them into one timeline with explicit inferred-link edges was `[Not found]`.
4. **Interoperable capsule** — HAR + OTLP + your envelope means Chrome DevTools, Proxyman, Langfuse, Phoenix, AgentLens all open your incident. Interop spreads faster than lock-in.
5. **LLM-ready incident brief** — a Markdown export designed to be pasted into any assistant: timeline, the interrupted call, the first divergence, cost, and pointers into the capsule. Low tech, high leverage; must be benchmarked (brief vs stack trace, blinded) before claiming it improves diagnosis.

What is **not** reachable and should be stated as non-goals: deterministic re-execution (rr/TTD class), observing closed desktop apps without hooks/proxy, hallucination detection, power-loss zero-loss, "everything the application does".
