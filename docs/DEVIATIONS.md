# Deviations (append-only)

A deviation is only recorded when it cannot be avoided; the plan and `docs/format.md` change in the same commit.

| # | date | finding / reason | plan section | change | why it is safe |
|---|---|---|---|---|---|
| DV-001 | 2026-11-14 | F4 (review finding) | §8.7 | `.seal` `body_len`, `body_crc32`, `body_hash` are defined over the **uncompressed** body; the codec lives in the segment header | byte layout unchanged; approved as confined to P1-13 |
| DV-002 | 2026-11-14 | the segment magic in §8.7 is 7 characters in an 8-byte field | §8.7 | `42 42 58 53 45 47 32 00` — `BBXSEG2` + NUL pad; all four magics now stated in hex | fixes an ambiguity in the plan, no behaviour change |
| DV-003 | 2026-11-14 | `host_fingerprint` used `socket.gethostname()`, which P0-14 forbids outside the proxy | §8.2 `0x048` | `platform.node()` — same OS hostname, no `socket` import, no resolver | the field still hashes hostname+os+machine |
| DV-004 | 2026-11-14 | `BBX-E140` was reused for "segment preallocation failed" while the registry/plan define it as a proxy allowlist error | §19 | preallocation/orphan-segment cases use `BBX-E133`; registry compared against the plan appendix by a test | removes a collision |
| DV-005 | 2026-11-14 | D-007 was recorded as a *plan default*; it is a **format freeze** (C4) | §8.3, §8.7, P1-01 | one checksum in v2: CRC-32/ISO-HDLC (`zlib.crc32`) for frame, head, meta, segment header and `.seal`; pure-Python CRC32C deleted; check value `0xCBF43926` in `docs/format.md` and `tests/conformance/vectors/crc32.json`; `meta.flags` bit 2 reserved-and-must-be-0 (`BBX-E221`); every `*_crc32c` renamed `*_crc32` | a CRC only detects torn/stale frames — tamper evidence is the BLAKE2b chain; the second algorithm cost 110 us/KiB (vs 0.58) and every reader an implementation |
| DV-006 | 2026-11-14 | S17 (C5) needs the app to survive ENOSPC at preallocation, but `roll()` raised `BBX-E132` into the app and closed the active segment before discovering it had nowhere to go | §8.6, P1-20 | `roll()` reserves segment `n+1` **first** (`segments.reserve`), and on `PreallocError` degrades in place: head flag `DEGRADED_NO_SPACE`, one `DEGRADED` frame, active segment unchanged, mapping unchanged, returns `False`. An append that then finds no room drops and counts the frame (`dropped_events`) instead of raising | no byte of the format changes; the crash-state and recovery semantics are unchanged, and the failure now matches the plan's "app unaffected" |
