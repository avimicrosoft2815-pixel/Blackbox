## 1. What this repository is

A local-first flight recorder for programs that call a model over HTTP. There is no server, no account, no
network egress of its own, and **no runtime dependency** — core is stdlib only, enforced by a test.

It is four things stacked, and each one only makes sense on top of the one below:

1. **A tape** — rolling preallocated segment files, each a 4096 B header followed by fixed-layout frames, plus a
   512 B `head` file whose 64 B slots are the *commit point*. Append-only, sealed with a footer, chained with
   BLAKE2b, and readable back by a backward scan that never trusts a torn frame.
2. **A recovery engine** — a scanner, a repair path for interrupted rolls, and an eight-step state machine that
   turns a tape left by a dead process into a `.bbx` capsule with a sha256 root. Each step is resumable and
   idempotent, and that is proven by killing the process at each step in three modes.
3. **Capture** — three in-process seams (httpx event hooks → transport tee → SDK method patches), a sink that
   turns the observed stream into `MODEL_REQUEST` / `MODEL_CHUNK` / `MODEL_RESPONSE` frames, and a loopback HTTP
   proxy that records any client that honours a base-URL variable.
4. **Attach surfaces** — the launcher (`blackbox run -- cmd`), the Claude Code and Codex hook adapters, and the
   inbox fold that gives the hook vantage its own tape.

The discipline around the code is unusual and is part of the product: a frozen format document, an error
registry with 48 codes that a test compares against the plan, a decisions ledger (D-001…D-042), a deviations
ledger (DV-001…DV-014), a defect list with seeds and reproductions, a forbidden-word rule enforced over the whole
tree *and* over commit messages, and a documentation test that fails when the stated test count is not the count
collection produces.

**There is no UI in this repository.** No HTML, CSS or JS file exists; `src/blackbox/ui/` does not exist. The
viewer is planned (plan §19.2, tickets P4-10/P4-11) but not started. That matters for the instruction about
"0 UI changes" — see §11, question 2.

## 4. The write path, in order

This is the part every other claim rests on, so it is worth stating exactly.

```
emit(kind, payload)                                     api.py:196
  └─ recording()                                        api.py:181   in-flight counter, so uninstall cannot close under a call
     └─ TapeWriter.emit                                 writer.py:194
        └─ _append_locked                               writer.py:249
           ├─ too big for a segment?  → BBX-E225
           ├─ no room and roll() failed? → drop, count, return   (degraded, never raises)
           ├─ _reserve(size)            → offset in the batch buffer
           ├─ frame.encode_into(...)    → payload, trailer, header, CRC   (frame.py:34)
           └─ head_seq/head_off advance in memory only
        └─ publish()                                    writer.py:288
           ├─ CHAIN frame for the batch (if enabled), roll first if it will not fit
           ├─ _flush_buf()              → ONE pwrite of the whole batch     ← data reaches the file
           └─ _head.publish(slot)       → ONE 64 B pwrite into the other slot ← COMMIT POINT
```

Three consequences, all tested:

* A reader only trusts frames at or below the published `head_off`, so a crash anywhere before the head
  `pwrite` costs the batch and nothing else (stop S3), and a crash after it loses nothing that was committed
  (stop S5).
* `mode=process` costs **no** sync syscall on the app thread. `kernel`/`paranoid` add group-commit
  `fdatasync` (250 ms / 1 MiB, or forced), and a keeper thread drains the window so the app thread never
  waits on a device.
* A roll reserves segment *n+1* **before** sealing *n* (`writer.py:470`). That is deliberate: discovering
  `ENOSPC` after sealing leaves the writer with no segment to write into, so the failure is turned into a
  `DEGRADED` head flag and a counted drop instead (S17, C5).

## 5. The read path

`scanner.scan(data_dir, writer)` (285 lines) is the only thing that decides what a tape *contains*:

1. `meta` and `head`; both slots invalid with frames present ⇒ `BBX-E220`, no frames present ⇒ empty tape.
2. The active segment is walked **backwards** from `head_off`; the walk stops at the first frame whose trailer
   or CRC does not check out, and a mismatch between the last valid frame's end and `head_off` is reported as
   `truncated_tail` rather than silently repaired.
3. Sealed segments are read forwards to `body_end` from the footer, so a compacted segment (smaller on disk)
   reads the same as an uncompacted one.
4. `GAP` frames declare holes; missing sequences are computed from the lowest sequence a reader can still
   reason about (`min(first frame, first GAP.from, tail_seq+1)`) and merged into runs with a per-run reason.
5. `verify_chain` walks level 1 (`CHAIN` frames) and level 2 (segment `prev_chain`), and checks that each
   declared hole's `prev` value is one the walk actually passes — that is the difference between a tombstone
   and corruption.

`recovery.Recovery.run` then wraps that in eight steps, each writing `recovery.done.<STEP>` with
`{input_hash, output_hash, artifact}`. A step is skipped only when the marker exists, the input hash still
matches **and** the artifact still hashes to its recorded output. Ten recoveries produce one capsule hash
(I6), and each step is killed in three modes (`before`/`mid`/`after`) as a test.

## 6. Capture, proxy and attach — the three vantages

| Vantage | Mechanism | What it can say | What it cannot |
|---|---|---|---|
| SDK (seam A/B) | httpx event hook, or wrapped transport | wire bytes, chunk counts, first-byte and total latency | calls that bypass httpx |
| SDK (seam C) | patched SDK methods | that the call happened, its parameters, event counts | byte counts — `partial=True` by construction |
| Proxy (seam D) | loopback listener | byte-exact body both directions, both disconnect classes | the application's own node structure |
| Hook adapters | agent settings + `blackbox ingest` | tool calls, prompts (hashed), turn boundaries | anything the agent does not hook |

The four are tied together only by `rec/links.py`, and only in three classes — and a link is a *record about*
two runs: nothing in the codebase can rename, move a frame, or merge a run.

Fail-open is enforced at one place (`cap_sdk/failopen.py`), because the per-chunk path once escaped into the
application (defect 27, reproduced at `ee210ae`). The proxy repeats the rule for its own receiver calls, and
counts them in `ProxyStats.record_errors`.

## 7. Contracts the code is held to

* **Failure classes F1–F4** are never conflated (`docs/guarantees.md`). `mode=process` claims F1 only;
  `kernel`/`paranoid` add F2; F3 is never claimed; F4 is what the CRC and the declared holes cover.
* **Invariants I1–I11** (plan §8.10) each have a named test mechanism. I1 (append-only, `GAP` before unlink),
  I3/I4 (`scan` returns exactly the committed prefix, never more), I6 (recovery idempotent), I7 (a visible
  `.bbx`/`.seg` is complete), I9 (chain verifies, a retention hole is declared), I10 (a sealed segment is
  immutable), I11 (no `SIGBUS` path into the user's process).
* **One checksum.** CRC-32/ISO-HDLC everywhere; meta bit 2 is reserved and must be 0, and a reader refuses a
  tape that sets it. No algorithm selector exists to drift.
* **Redaction before persistence.** The sink is handed a redactor; what it frames is already clean, and the
  summary carries counts by kind and never bytes. `content=hash` is the default, so the tape does not keep the
  model's text unless the user asks.
* **Fail-open everywhere the application is on the other side.** `install()`, `emit()`, the seams, the proxy,
  the ingress command and the hook fold all convert their own failures into counters.
* **No egress except the proxy's table.** `tests/test_no_egress.py` forbids socket/urllib/http/ssl literals in
  `src/` and asserts the proxy's reachable set from the route table.

## 9. Findings — what I would change, in priority order

Each one is a file and a line, and each is a **change to the tree**, not a change to the mechanism.

### F-1 · The README contradicts the tree and the licence metadata

`README.md:3` says "storage and recovery layer only; no SDK, proxy or viewer yet"; `:22` says "157 tests"; `:34`
says "No capture API, no proxy, no viewer, no CLI beyond `--version`/`status`, no database, no retention, no
capsules"; `:37-40` says "Licence: None yet … there is no `LICENSE` file and no `license` field in
`pyproject.toml`".

All four are false today: the suite is 841 tests, capture/seams/proxy/launcher/hooks/retention/capsules all
exist, and `pyproject.toml:11` declares `license = { text = "Apache-2.0" }` **while no `LICENSE` file exists**.

The licence sentence is the one that carries risk: the metadata asserts a licence the repository does not
contain, and the README says the opposite. This is not a UI question; it is the file a stranger reads first.

### F-2 · Two different "default data directory" rules, three ways

| Caller | Default | Line |
|---|---|---|
| `api.install()` | `./.blackbox` (cwd) | `api.py:109` |
| `rec.launcher.launch()` | `.` (cwd) | `launcher.py:276` |
| `hooks.inbox.default_dir()` | `~/.blackbox/inbox` | `inbox.py:91` |
| `config.Config` | `~/.blackbox` | `config.py:37` |
| `keys.default_key_path()` | `~/.blackbox/keys/redaction.key` | `keys.py:48` |

Consequences that a user meets immediately: a bare `blackbox run` writes tape data into the current directory,
while the redaction key lives in the home directory; and a hook event written by `blackbox ingest` with no
environment goes to `~/.blackbox/inbox`, which the launcher (folding `$data_dir/inbox`) will never read. The
launcher sets `BLACKBOX_INBOX`, so this is only wrong for out-of-band installs — but it is wrong silently, and
there is no test that pins the default.

### F-3 · `docs/guarantees.md` is stale in both directions

It marks `process` (the default mode) "in progress (P1-08)" and `kernel`/`paranoid` "planned", and its
claims → tests table names test files that do not exist (`tests/kill/test_kill_stages.py`, `tests/test_head.py`,
`tests/test_prealloc_sigbus.py`). The real files are `tests/test_crash_points.py`, `tests/test_tape.py` and
`tests/test_prealloc.py`. `docs/format.md` does not mention this table, and no test guards it, so it drifts
freely. This is the document that defines what the product may claim, which makes it the worst one to have
stale.

### F-4 · `docs/STATUS.md` keeps defect 26 open after it was fixed

`docs/STATUS.md` says "Defect 26 is open and cannot be closed here: on Windows, `install(data_dir=<a file>)`
reported `enabled: True`". The repair is in the tree at `api.py:114-115` (refuse an existing non-directory by
name, platform-independent) and is tested at `tests/test_failopen.py:152` and
`tests/test_api_lifecycle.py:121`. The status file is the ledger of record; it should say "fixed, POSIX-verified,
Windows cell pending".

### F-5 · `src/blackbox/__init__.py` exports nothing but the version

`__all__ = ["__version__"]`, and the docstring still says "no capture API yet". So `import blackbox;
blackbox.install()` raises `AttributeError`, while `from blackbox import api; api.install()` works. Every other
place in the tree treats `api.install` as *the* entry point (the plan's §11.1 has 11 entry points). This is an
API-surface gap, not a bug: nothing is broken, but the obvious thing does not work and the docstring says the
wrong reason why.

The `status` line in `__main__.py:37-38` has the same problem: `blackbox status` prints "no SDK, proxy or viewer
yet" and "pre-alpha, storage and recovery layer only".

### F-6 · Two tests import an optional dependency without `importorskip`

`tests/test_headers.py:93` and `:187` do a bare `import httpx`. Every other optional-integration test in the
suite uses `pytest.importorskip`, which is what `pyproject.toml`'s comment promises ("the suite skips them when
it is absent"). Without the extra, these two fail with `ModuleNotFoundError` instead of skipping, which turns a
documented-optional install into a red suite.

### F-7 · The stated test count depends on the environment

`docs/STATUS.md` says "Total: 841 tests" and `test_the_test_count_line_matches_the_suite_size` enforces it — but
841 is only true with `httpx`, `openai` and `anthropic` installed. On a clean venv the same line fails at 745.
The test is right to exist; the fix is either to make the count extra-independent (count collected + skipped) or
to state the environment beside the number.

### F-8 · A segment's header says `start_seq = 0`, always

`segments.finish` writes the header with `start_seq=0` (`segments.py:95`) even though the frame range is known
later, and nothing rewrites it. The seal footer carries the true range (`_segment_range`, `writer.py:538`), so no
reader is misled **today** — but the header field is a documented part of the format (`docs/format.md` §5) and a
future reader that trusts it will be wrong. Either the field should be filled at seal time (a header rewrite
invalidates its CRC, so it would have to be part of `finish`) or `docs/format.md` should say the field is
reserved and always 0.

### F-9 · `redact.py` has a duplicated docstring statement

`Redactor`'s docstring appears at `redact.py:140` and again as a bare string literal at `:158`. The second is a
no-op expression. Harmless at runtime; it is the kind of thing a reviewer stops on.

### F-10 · A roll reads its own segment back twice, in full

`_read_body` (`writer.py:523`) reads the committed prefix, and `_segment_range` (`writer.py:538`) opens the
segment again and **decodes every frame** to recover `(start_seq, end_seq, frame_count)`. On every roll and on
close, that is a full parse of up to `segment_bytes` — 16 MiB by default. The numbers in §8 show it is not
currently a problem (rolls are rare relative to events), but it is the largest avoidable cost in the tape layer,
and it is also the only place where a *legitimate* frame that fails to decode silently truncates the reported
range. Tracking the three values incrementally in the writer would remove both.

### F-11 · `_read_meta` catches `(FileNotFoundError, Exception)`

`recovery.py`'s `_read_meta` catches `FileNotFoundError` and `Exception` in the same tuple, which is
self-cancelling: the first is already covered. Behaviourally fine, reads as a mistake.

### F-12 · Minor: dead branch after `rebuild_head`

`writer.open()` calls `repair.rebuild_head` when the head is unreadable, then tests `if best is None: if
existing: raise TapeError(...)`. Reaching that raise means the rebuild returned `None`, which only happens when
the newest segment is damaged — so the message ("run recovery") is right but the branch is a second opinion that
duplicates F-1's rebuild.
